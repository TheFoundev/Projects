Four tasks, in the right order, every time.

A small task graph for a nightly batch: extract writes the orders, clean drops the impossible rows, aggregate sums the revenue per category and load writes the result into a SQLite warehouse. The runner walks the dependencies of the last task and executes every one of them in order.

Architecture

How it works

Every task is a class with a requires method that names the tasks it needs, an output method that returns the marker file of the task, and a run method that does the work. The runner resolves the dependencies recursively, so the load task pulls in the aggregate, which pulls in the clean, which pulls in the extract. Each task leaves a done.json marker with the number of rows it wrote, and the load step writes the category summary into a SQLite warehouse.
