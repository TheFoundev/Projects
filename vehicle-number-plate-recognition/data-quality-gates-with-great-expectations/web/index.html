What it does

The capabilities

Every panel below is served by the real API of this project — nothing here is a mock-up.

⌕

Every check is written once

The check says what it looks at and how bad it is, and the report and the cleaning follow it.

⊘

Critical failures block the load

The rows of a critical check are thrown away, so a bad row never reaches the warehouse.

⚠

Warnings are only warnings

A row that fails a warning is reported and kept, because it is not that bad.

▤

The rows are named

The report says which customer failed which check, with an example of every failure.

⛭

The gate always answers

The report ends with a verdict: the load passes or it does not.

⛁

The checks are plain functions

No suite file and no framework: the checks are readable Python that pandas runs.

Architecture

How it works

The checks are small classes: a column has to be there, a value may not be empty, may only be there once, has to match a pattern, has to be inside a range or has to be one of a set. Each of them gives the rows that failed it, so the report can name the rows and the checks they failed. The failures of the critical checks throw their rows away, the warnings are only reported, and the report and the cleaned table can never disagree because both come from the same checks.

The API

Endpoints

MethodPathWhat it does
GET/api/summaryThe state of the last gate: the rows, the clean rows and the failures by severity
GET/api/checksEvery check with its severity, its failures and whether it passed
GET/api/failuresThe rows that failed a check, with the checks they failed
POST/api/runRun the gate again and answer with the new summary
GET/console.htmlThe console of this site
GET/assets/theme.cssThe design system of this site
