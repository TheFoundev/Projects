commerce & retail

A shop, a cart and a checkout that keeps the stock honest.

Saleor runs a product catalogue with prices in cents and a stock count, a session cart that never offers more than there is, a checkout that validates the stock and takes it in one transaction, and a small GraphQL endpoint that answers with the products, the orders and the channels.

What it does

The capabilities

Every panel below is served by the real API of this project — nothing here is a mock-up.

◆

A catalogue with a real stock

Every product has a price in cents and the number of units that are on the shelf.

▤

A cart that respects the stock

The cart never holds more units of a product than the shop has, and it says so when a product runs out.

✓

A checkout that either happens or does not

The stock is checked again and taken in one transaction, so an order is never half written.

⛨

A GraphQL endpoint over the same data

The query is parsed by a GraphQL library, so only the fields that are asked for are read.

⌗

The order keeps what was bought

Every line of an order holds the name and the price of the product at the moment of the purchase.

⧉

The shop and the desk in one application

The storefront and the resource views of the admin are the same process and the same database.

Architecture

How it works

The state of the shop is a SQLite database whose tables are described in config.json: the resources, their fields and the seed rows are created when the application starts. The cart lives in the session of the visitor, the checkout reads the stock of every product again, writes the order and the order lines and takes the units in one transaction, and a rollback puts the stock back when a line cannot be served. The GraphQL endpoint is a real schema over the same tables, so a query answers with the fields that were asked for and the variables are used.

The API

Endpoints

MethodPathWhat it does
GET/api/summaryThe products, the orders, the revenue and the open orders of the shop
GET/api/metaThe resources, their fields and the features of the shop
GET/api/productsThe catalogue, newest first
GET/api/ordersThe orders of the shop, newest first
POST/api/productsCreate a product (a signed-in account is needed)
POST/graphqlAsk the shop for its products, orders or channels
GET/storeThe storefront of the shop
POST/api/sessionSign in with the email and the password of an account
