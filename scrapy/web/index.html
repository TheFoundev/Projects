Every page of a site, with its links and its breaks.

Crawler walks a site breadth first, reads the title, the links and the paragraphs of every page it finds, stops at the depth you allow, and writes the index of the pages it saw and the links that were broken.

What it does

The capabilities

Every panel below is served by the real API of this project — nothing here is a mock-up.

◆

A real index of the site

Every page the crawler opened stands in the console with its title and its number of links.

◷

A depth you decide

The crawl stops at the depth that is given, so a deep site does not run away.

⛨

Only the same host

A link that leaves the host is not followed, so the crawl stays where it was told to stay.

✓

The broken links are found

A page that cannot be opened is reported instead of being skipped quietly.

▤

A parser, not a soup of regexes

The titles and the links are read with a html.parser, so the markup is understood.

↻

A new crawl on demand

The console starts a new crawl and shows the index it produced.

Architecture

How it works

The target of the crawl is a small site the project writes itself, so the run needs no network and no permission. A html.parser parser pulls the title and the links out of every page, the links are made absolute and queued with the depth of the page they were found on, and only the links of the same host are followed. The result is written to artifacts/pages.jsonl, one line per page, and the URLs that could not be opened are written to artifacts/broken.txt.

The API

Endpoints

MethodPathWhat it does
GET/api/summaryThe pages, the links and the broken links of the last crawl
GET/api/pagesThe index of the pages, with the title and the links of every page
GET/api/brokenThe links that could not be opened
POST/api/crawlCrawl the site again and answer with the new index
GET/console.htmlThe console of this site

Run it locally
